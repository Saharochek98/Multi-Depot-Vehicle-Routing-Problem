# Быстрая реконфигурация маршрутов MDVRP

Решение задачи № 1 по многоскладской маршрутизации транспорта (**Multiple Depot Vehicle Routing Problem, MDVRP**) при отмене части доставок.

## Постановка задачи

Имеется ориентированный взвешенный граф $G=(V,E)$, где $V=D\cup C$: $D$ — склады, $C$ — клиенты. Вес $d(u,v)\ge0$ задаёт стоимость направленного переезда. За каждым складом закреплено $A$ автомобилей. Каждый автомобиль начинает и завершает маршрут на своём складе; один маршрут содержит не более $M$ клиентов; каждый клиент обслуживается ровно один раз.

Пусть вечером построено исходное оптимальное решение $R^*$. Утром клиенты из множества $\Delta C$ отменили заказы. Требуется быстро получить маршруты для $C'=C\setminus\Delta C$, минимизируя суммарную стоимость:

$$
\min_{R'}\sum_{r\in R'}\operatorname{cost}(r),
\qquad
\operatorname{cost}(r)=\sum_{j=0}^{|r|}d(v_j,v_{j+1}),
$$

где $v_0=v_{|r|+1}$ — склад маршрута.

## Идея метода

Используется **warm start + локальный поиск**, без повторного решения полной NP-трудной задачи.

1. **Удаление отменённых клиентов.** Исключаем $\Delta C$ из готовых маршрутов $R^*$. Полученный план допустим: все оставшиеся клиенты обслуживаются один раз, количество клиентов не растёт, автомобили остаются при своих складах.
2. **Relocate.** Рассматриваем перенос одного клиента между двумя существующими маршрутами, если соблюдается ограничение $M$ и снижается суммарная стоимость.
3. **2-opt.** Рассматриваем разворот сегмента внутри маршрута. Для ориентированного графа пересчитывается **полная стоимость**, так как стоимости прямых и обратных дуг могут различаться.
4. **Остановка.** Повторяем лучшее найденное улучшение до локального оптимума либо до заданного лимита времени.

Это **эвристика**, а не алгоритм гарантированного глобального оптимума. Она предназначена для быстрого пересчёта уже допустимого решения. Лимит времени проверяется между итерациями поиска; отдельная итерация может немного превысить указанный интервал.

Нужен **Python 3.9+**.

```bash

```

```text

```

Для собственных данных вызовите:

```python
new_routes, total_cost = replan(
    routes=old_routes,       # {(depot_id, car_id): [client_id, ...]}
    cancelled={6},           # идентификаторы отменивших клиентов
    dist=distance_matrix,    # dist[u][v] — направленная стоимость
    capacity=3,              # M — максимум клиентов на маршрут
    seconds=1.0,             # ориентировочный бюджет оптимизации

```

Матрица `dist` должна содержать стоимость каждой дуги, используемой в маршрутах. Исходные маршруты должны быть допустимыми и содержать **каждого исходного клиента ровно один раз**. Список машин сохраняется, даже если некоторые маршруты пустые.

## Оценка и ограничения

Пусть $n$ — число активных клиентов, $q=K A$ — число автомобилей, $M$ — максимальная длина маршрута. В наивной реализации поиск relocate за итерацию занимает до $O(nqM^2)$ операций на пересчёт пути, а 2-opt — до $O(qM^3)$. Это оценка одного полного прохода; число проходов зависит от улучшений и ограничения времени.

Преимущества: повторное использование $R^*$, простая реализация, учёт асимметричной матрицы, сохранение ограничений. Ограничения: локальный оптимум вместо глобального; не выполняется переназначение автомобиля другому складу; метод не создаёт новые маршруты; не учитываются веса грузов и временные окна (в исходной задаче ограничено именно **число клиентов**).

## Вывод

Удаление отменённых заказов сразу даёт допустимый план, а операции relocate и 2-opt могут уменьшить его стоимость без полного пересчёта MDVRP. Метод реализует быстрое **приближённое** перепланирование, но не доказывает оптимальность результата.
